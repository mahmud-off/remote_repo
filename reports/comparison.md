# Сравнение трёх SAST-анализаторов

Инструменты и версии (см. `reports/versions.txt`):

| Инструмент | Версия | Тип анализа |
|------------|--------|-------------|
| Cppcheck | 2.10 | Собственный AST-движок, проверка памяти/стиля, частичный dataflow |
| Clang Static Analyzer | Debian clang 14.0.6 (`clang --analyze`, чекеры security,core,unix) | Межпроцедурный symbolic path-sensitive анализ |
| Flawfinder | 2.0.20 | Лексический поиск паттернов опасных функций (regex-based) |

**Примечание:** план лабораторной предполагал Microsoft Visual Studio Code
Analysis (`cl /analyze`) в качестве второго инструмента. Проверка выполнялась в
Linux-окружении, где MSVC недоступен, поэтому он заменён на Clang Static
Analyzer — независимый SAST того же класса (path-sensitive анализатор на базе
компилятора). Требование «три разных SAST» сохранено: Cppcheck, Clang Static
Analyzer, Flawfinder используют принципиально разные движки и не являются
повторными запусками одного инструмента.

## До исправления (`vulnerable/src/main.cpp`)

| Инструмент | Всего находок | Находок по нашему коду | Нашёл BUG-1 (CWE-120, strcpy) | Нашёл BUG-2 (CWE-78, system) | Уникальные находки | Ложные срабатывания | Пропущенные намеренные ошибки |
|------------|---------------|------------------------|-------------------------------|------------------------------|--------------------|---------------------|-------------------------------|
| Cppcheck 2.10 | 4 сообщения | 1 | **нет** | **нет** | `constParameter` (argv) — стилистическая | Да: style/config-подсказки (argv const, ConfigurationNotChecked в zconf.h ×2), к реальным уязвимостям не относятся | Обе (BUG-1 и BUG-2) |
| Clang Static Analyzer 14.0.6 | 1 предупреждение | 1 | **да** (`security.insecureAPI.strcpy`, main.cpp:54) | **нет** | Обнаружил strcpy через полноценный path-sensitive анализ, а не по имени функции | Нет | BUG-2 (инъекция команд) |
| Flawfinder 2.0.20 | 3 hits (Hits = 3; level 4 ×2, level 2 ×1) | 3 | **да** (строки 54 и 50) | **да** (строка 84) | Единственный, нашёл `system` (BUG-2); также flagged фиксированный массив (стр. 50) | Частично: hit уровня 2 на объявление `char comment[64]` — это не самостоятельная уязвимость, а контекст к BUG-1 | Нет |

### Выводы до исправления

- Ни один инструмент не нашёл обе ошибки одновременно → сравнение показывает
  взаимодополняемость подходов.
- Flawfinder (лексический) дал наибольший охват именно по намеренным дефектам,
  но без подтверждения достижимости (каждый hit требует ручного разбора).
- Clang SA подтвердилstrcpy межпроцедурным анализом, но пропустил CWE-78.
- Cppcheck оказался наименее результативным: обе намеренные ошибки пропущены,
  найдены только style/config замечания.

## После исправления (`fixed/src/main.cpp`)

| Инструмент | Остались ли TP-находки | Результаты повторного запуска | Комментарий |
|------------|-----------------------|-------------------------------|-------------|
| Cppcheck 2.10 | нет | Те же 2style/config замечания: `constParameter` (main.cpp:27) и `ConfigurationNotChecked` (zconf.h zlib 1.3.1) | Подтверждённых дефектов нет; найденное — FP/шум, существовал и до исправления |
| Clang Static Analyzer 14.0.6 | нет | 0 предупреждений (`reports/fixed/clang-sa-console.txt` пуст) | Находка по strcpy исчезла после замены на контролируемое усечение |
| Flawfinder 2.0.20 | нет | `No hits found` (Hits = 0, все уровни) | Исчезли все 3 хита: нет `strcpy`, нет `system`, нет фиксированного C-буфера |

Также в `fixed/` зависимость обновлена zlib 1.2.11 → 1.3.1, что устраняет
CVE-2018-25032 (SCA-часть требования по зависимостям).

## Общая оценка

| Критерий | Cppcheck | Clang Static Analyzer | Flawfinder |
|----------|----------|-----------------------|------------|
| Попадание в намеренные дефекты (2 всего) | 0/2 | 1/2 | 2/2 |
| Ложных/шумовых находок | 3 | 0 | 1 (контекстный hit) |
| Скорость/простота запуска | средняя (нужен `--force` из-за #ifdef) | требует настройки include-путей | минимальная |
| Класс анализа | гибрид (AST+частичный dataflow) | path-sensitive | лексический |

Результаты трёх инструментов существенно различаются, что и демонстрирует цель
лабораторной работы: ни один SAST сам по себе не покрывает все классы дефектов;
лексический сканер даёт широкий охват с ручным triage, path-sensitive анализатор
— высокую точность подтверждённых находок, универсальный линтер — низкий выход
по security-дефектам в данном примере.
